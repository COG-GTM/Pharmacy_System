2. AWS Target Architecture Overview

The target architecture modernizes the monolith into a containerized deployment on AWS using managed services for data, messaging, storage, and observability. The design follows AWS Well-Architected Framework pillars: Operational Excellence, Security, Reliability, Performance Efficiency, Cost Optimization, and Sustainability.

Design Principles: Lift-and-containerize first, then progressively decouple. Use managed services to eliminate undifferentiated heavy-lifting. Keep the Laravel application core intact initially — swap infrastructure dependencies (database, queue, cache, storage, email) to AWS-native equivalents.

Service Definitions

ECS ServiceCommandCPU / MemoryScaling
Web Servicenginx + php-fpm0.5 vCPU / 1 GBTarget tracking: CPU 60%, 2–10 tasks
Worker Servicephp artisan queue:work sqs --tries=30.25 vCPU / 0.5 GBSQS-based: scale on ApproximateNumberOfMessages, 1–5 tasks
Scheduler Servicephp artisan schedule:work0.25 vCPU / 0.5 GBFixed: 1 task (singleton)

Container Image Strategy

  • Single Dockerfile producing a multi-stage image: Composer dependencies → npm build → production image with Nginx + PHP-FPM
  • Amazon ECR as the private container registry with image scanning enabled
  • ECS services differ by command override at task definition level, not by image
  • Environment variables injected via AWS Secrets Manager + ECS task definition secrets field
Why Fargate over EKS? The Pharmacy System is a single-application workload without complex service mesh requirements. Fargate reduces operational overhead — no cluster management, patching, or node scaling. If future microservice extraction demands advanced orchestration, migration to EKS is straightforward.

5. Data Layer — Aurora MySQL & ElastiCache

DB Amazon Aurora MySQL

  • Engine: Aurora MySQL 3.x (MySQL 8.0 compatible)
  • Instance: db.r6g.large (Multi-AZ)
  • Storage: Aurora auto-scaling (10 GB – 128 TB)
  • Replicas: 1 reader replica for read-heavy DataTable queries
  • Backups: Continuous backups with 7-day PITR
  • Encryption: At-rest (KMS) + in-transit (TLS)

Migration from MySQL to Aurora

  • Use AWS DMS for initial full-load + CDC replication
  • Run php artisan migrate against Aurora to validate schema compatibility
  • Enum columns are fully supported in Aurora MySQL

RD Amazon ElastiCache (Redis)

  • Engine: Redis 7.x (cluster mode disabled)
  • Instance: cache.r6g.large (Multi-AZ)
  • Use Cases:
Use CaseLaravel Config
Session storageSESSION_DRIVER=redis
Application cacheCACHE_DRIVER=redis
Rate limitingBuilt-in Laravel rate limiter
Why Redis over DynamoDB for sessions? Laravel has first-class Redis support. Switching SESSION_DRIVER to redis is a single env-var change with zero code modifications.

6. Object Storage & CDN

S3 Amazon S3

Replace Laravel's local filesystem with S3 for durable, scalable file storage.

Content TypeS3 Bucket / PrefixAccess
Prescription imagespharmacy-files/prescriptions/Private (pre-signed URLs)
User avatarspharmacy-files/avatars/Public via CloudFront
Vite build assetspharmacy-assets/Public via CloudFront

Laravel Configuration

  • Set FILESYSTEM_DISK=s3
  • Configure AWS_BUCKET, AWS_DEFAULT_REGION
  • Use IAM task role (no access keys in env)
  • Enable S3 bucket versioning for prescriptions
  • Lifecycle policy: move to S3-IA after 90 days

CF Amazon CloudFront

Global CDN for static assets and avatar images.

  • Origin 1: ALB (dynamic requests) — cache disabled
  • Origin 2: S3 (static assets) — TTL 30 days
  • Origin 3: S3 (avatars) — TTL 7 days
  • HTTPS-only with ACM certificate
  • Gzip/Brotli compression enabled
  • Cache behavior paths:
    • /build/* → S3 assets origin
    • /avatars/* → S3 avatars origin
    • Default (*) → ALB origin

8. Notification Services

SE Amazon SES (Email)

Replace Mailtrap SMTP with Amazon SES for production email delivery.

  • Laravel config: MAIL_MAILER=ses
  • Verify sending domain via DNS (DKIM + SPF)
  • Request production access (move out of sandbox)
  • Configure bounce/complaint SNS topics
  • Estimated volume: < 1,000 emails/day

Email Types

WS Real-Time Events

Two options for replacing Pusher:

Option A: Keep Pusher (Recommended for Phase 1)

  • No code changes needed
  • Pusher free tier supports 200K messages/day
  • Store keys in Secrets Manager

Option B: AWS IoT Core + WebSockets (Phase 3)

  • Full AWS-native solution
  • Custom Laravel broadcasting driver
  • Higher implementation effort
  • Better for high-scale scenarios

11. Security & Compliance

Secrets Management

DB credentialsSecrets Manager (auto-rotated)
Stripe API keysSecrets Manager

IAM & Access Control

  • ECS Task Role — least-privilege policy for S3, SQS, SES, Secrets Manager
  • ECS Execution Role — ECR pull + CloudWatch Logs + Secrets Manager read
  • No hardcoded credentials — all access via IAM roles
  • AWS WAF — OWASP Top 10 rule set on CloudFront
  • ACM — Managed TLS certificates (auto-renewed)

Compliance Checklist

  • Encryption at rest: Aurora (KMS), S3 (SSE-S3), ElastiCache (KMS), EBS (KMS)
  • Encryption in transit: TLS everywhere (ALB, Aurora, Redis, S3)
  • VPC Flow Logs enabled and sent to CloudWatch Logs
  • AWS CloudTrail enabled for API auditing
  • Prescription images stored with S3 Object Lock (compliance mode) if HIPAA applies
  • ECS containers run as non-root user
  • ECR image scanning on push

Cost Optimization Strategies

  • Fargate Spot: Use for worker tasks (tolerant to interruption) — up to 70% savings
  • Aurora Serverless v2: If traffic is bursty, switch to Serverless for pay-per-ACU pricing
  • ElastiCache Serverless: Consider for variable cache workloads

  • S3 Intelligent-Tiering: Auto-tier infrequently accessed prescription images
  • Right-sizing: Start small, use CloudWatch Container Insights to right-size after 30 days
Start Smaller: For development/staging, use Aurora Serverless v2 (min 0.5 ACU) and a single-node Redis to reduce costs to ~$250/month.

15. Risks & Mitigations

RiskImpactLikelihoodMitigation
Data loss during MySQL → Aurora migration High Low Use DMS with CDC replication. Validate row counts and checksums. Maintain source as fallback.
Enum column incompatibility Medium Low Aurora MySQL is fully MySQL-compatible. Test all migrations on Aurora before cutover.
Session loss during DNS cutover Medium Medium Migrate sessions to Redis before cutover. Redis is shared across old and new infra during transition.
File storage URLs break (local → S3) Medium Medium Update APP_URL and filesystem config. Use Laravel's Storage::url() facade consistently.
Increased latency from sync → async queue Low Low SQS adds ~10ms overhead. Order assignment already runs on a schedule. Net UX improvement.
Cost overrun Medium Medium AWS Budgets alerts at 80% and 100% thresholds. Monthly cost review. Start with smaller instances.
Stripe webhook delivery to new endpoint Medium Low Update Stripe webhook URL before cutover. Use Route 53 to ensure zero-downtime transition.
